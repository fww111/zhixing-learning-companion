# 智能辅导多智能体工作台设计规格

日期：2026-06-06

## 背景

项目当前已经具备课程级学生画像、课程知识库、Milvus 向量检索、MySQL 原文块、Neo4j 知识图谱、学习路径、学习评估和 OpenMAIC 标准课堂。用户希望在所有登录后的页面右下角提供智能辅导入口，学生可随时通过文字、图片、语音提问，系统基于当前课程本地知识库进行 RAG 增强回答，并以多模态形式辅助学习。

本功能采用已确认的“方案 C：多智能体工作台”。它不是普通聊天框，而是一个可视化的“分析、检索、生成、校验、决策”闭环辅导面板，既服务学生提问，也展示项目的多智能体协同能力。

## 目标

1. 在登录后的全局应用壳层右下角显示智能辅导悬浮入口。
2. 展开后显示多智能体辅导工作台，支持当前页面内直接提问，不破坏原有学习流程。
3. 所有回答必须优先绑定当前课程，并通过 Agentic RAG 使用课程本地知识库和知识图谱约束。
4. 支持文字输入、图片输入和语音输入入口。
5. 回答内容支持多模态卡片，包括文字讲解、图示说明、代码提示、练习建议、视频讲解脚本或 OpenMAIC 跳转建议。
6. 显示检索证据、图谱约束、校验结果和最终决策，让“多智能体协同闭环”对用户和评审可见。

## 非目标

1. 第一版不直接生成真实视频文件，只生成视频脚本、课堂片段建议或 OpenMAIC 跳转建议。
2. 第一版语音输入优先使用浏览器语音识别转文字，不引入新的后端语音识别服务。
3. 第一版图片输入可作为问题附件和上下文，若本地 OCR 或视觉模型不可用，则退化为要求学生补充图片描述。
4. 不改动现有课程知识库、知识图谱、学习路径、学习评估和标准课堂的核心页面流程。

## 用户体验设计

### 全局入口

悬浮入口挂载在 `AppLayout`，因此所有认证后的页面可见。入口固定在右下角，使用 Lucide 风格图标和现有产品色系，触控区域不小于 44px。入口不遮挡主要按钮；在小屏幕上保留底部安全距离。

入口状态：

- 未选择课程：显示“先选择课程”的轻提示。
- 已选择课程但未完成画像：允许提问通用课程问题，但提示“完成画像后可获得个性化辅导”。
- 已选择课程且知识库可用：显示“RAG 已连接”。
- RAG 服务异常：显示“本地知识库暂不可用，将使用降级回答”。

### 展开面板

展开后为右下角大型浮层工作台，默认宽度约 420-480px，高度不超过视口 80%。移动端切换为底部抽屉。

面板区域：

1. 顶部上下文栏：当前课程、当前页面、当前知识点、RAG 状态。
2. 智能体阶段条：分析、检索、生成、校验、决策。
3. 消息区：学生问题、AI 回答、证据引用和多模态卡片。
4. 证据区：MySQL 原文块、来源页码或章节、Milvus 检索轨迹、Neo4j 图谱关系。
5. 输入区：文字输入框、图片上传按钮、语音按钮、发送按钮。

### 多模态回答卡片

每次回答最多返回 3 类高价值卡片，避免窗口过载：

- `text_explanation`：结构化文字讲解。
- `diagram`：概念图、流程图或思维导图说明，可先用结构化数据和前端渲染实现。
- `code_hint`：代码片段、错误分析或浏览器运行建议。
- `exercise`：本知识点相关练习，不直接给编程题答案。
- `video_script`：短视频讲解脚本或 OpenMAIC 标准课堂跳转建议。
- `source_evidence`：本地知识库证据卡片。

## 后端设计

### API

新增接口：

`POST /api/tutor/chat`

请求字段：

- `course_id`: 必填，当前课程 ID。
- `message`: 必填，学生输入文本。
- `node_id`: 可选，当前知识图谱节点 ID。
- `page_context`: 可选，当前页面类型，例如 `courses`、`knowledge_base`、`graph`、`learning_path`、`learning`、`assessment`。
- `attachments`: 可选，图片附件元数据或上传后的文件标识。
- `history`: 可选，最近若干轮对话摘要。

响应字段：

- `answer`: 最终回答文本。
- `agent_events`: 多智能体阶段事件。
- `analysis_plan`: 问题理解、课程上下文、是否需要检索更多证据。
- `retrieval_trace`: Milvus 召回和 MySQL 原文块映射。
- `graph_constraints`: 当前节点、父章节、前置、后继、相关节点。
- `evidence_chunks`: 最终用于回答的 MySQL 原文块。
- `verification_report`: 事实约束和证据支撑检查。
- `decision_report`: `accepted`、`retrieve_more`、`revise` 或 `fallback`。
- `multimodal_cards`: 多模态回答卡片。
- `suggested_actions`: 继续学习、进入课堂、查看图谱、生成练习、重新规划路径等动作。

### 多智能体流程

1. `TutorAnalysisAgent`：识别问题意图、课程、页面、知识点和是否需要 RAG。
2. `TutorRetrievalAgent`：调用现有 `AgenticRAGService`，用 Milvus 召回候选，再从 MySQL 获取最终原文块，并加入 Neo4j 图谱约束。
3. `TutorGeneratorAgent`：基于证据生成回答和多模态卡片。
4. `TutorVerifierAgent`：检查回答是否被证据支持，标记无依据内容。
5. `TutorDecisionAgent`：决定接受、补检索、修订或降级回答。

第一版可先以同步闭环返回，后续再扩展为流式事件。

### RAG 约束

辅导回答必须满足课程隔离：

- 查询只使用当前 `user_id + course_id` 的知识库、图谱和画像。
- Milvus 只使用课程级集合。
- 最终证据只允许来自 MySQL `knowledge_chunks.content`。
- 如果当前问题绑定 `node_id`，检索必须加入该节点名称、父章节、前置和后继节点作为查询上下文。
- 如果没有知识库证据，回答必须明确提示“未检索到课程知识库证据”，并降低置信度。

### 历史与画像更新

第一版将每次辅导提问作为学习行为事件记录，事件类型使用现有 `tutor_question` 或扩展为 `tutor_question_asked`。后续画像随学随新阶段可根据问题类型、薄弱点、追问频率、证据主题来更新学生画像和学习路径。

## 前端设计

### 组件

新增组件建议：

- `TutorAssistantFloating`：全局挂载入口和展开状态。
- `TutorAssistantPanel`：工作台主体。
- `TutorAgentTimeline`：分析、检索、生成、校验、决策阶段条。
- `TutorMessageList`：消息和回答展示。
- `TutorEvidencePanel`：证据块和图谱约束展示。
- `TutorInputBar`：文字、图片、语音和发送入口。
- `TutorMultimodalCard`：多模态结果卡片。

### 挂载位置

`TutorAssistantFloating` 挂载在 `AppLayout` 的 `app-main` 外层或 `main.app-shell` 内部，避免被页面滚动区域裁切。组件通过当前路由解析 `course_id`，并在无路由课程 ID 时读取 `currentCourse`。

### 状态

前端状态包括：

- 是否展开。
- 当前课程 ID。
- 当前页面上下文。
- 当前知识点 ID。
- 输入文本。
- 附件列表。
- 语音识别状态。
- 当前会话消息。
- 请求加载和错误状态。

第一版会话可先保存在组件状态中，后续再落库为持久对话。

## 错误处理

1. 未登录：不显示辅导入口。
2. 未选择课程：面板提示先选择课程，不发送后端 RAG 请求。
3. 课程无知识库：允许提问，但提示需要先构建知识库才能获得课程证据。
4. Milvus 或 Neo4j 不可用：降级为 MySQL 关键词召回，并在证据区显示降级状态。
5. LLM 返回异常：显示可重试错误，不清空用户输入。
6. 图片或语音能力不可用：保留文本输入，显示明确说明。

## 测试策略

### 后端测试

1. `POST /api/tutor/chat` 未登录时拒绝访问。
2. 不同用户或不同课程不能读取彼此知识块。
3. 有 Milvus 召回时，响应证据块来自 MySQL。
4. Milvus 不可用时，降级到 MySQL 召回。
5. 带 `node_id` 时返回图谱约束。
6. 无证据时响应包含低置信度和降级说明。
7. `agent_events` 包含分析、检索、生成、校验、决策阶段。

### 前端测试

1. 登录后各路由显示悬浮入口，未登录不显示。
2. `/courses/:courseId/...` 页面自动绑定路由课程。
3. `/courses` 页面使用当前选中课程。
4. 无课程时发送按钮不可用或提示选择课程。
5. 发送文字问题后展示阶段条、回答、证据和多模态卡片。
6. 图片上传和语音按钮有明确状态，不出现静态不可点击控件。
7. 小屏幕面板不溢出视口。

## 实施顺序

1. 后端先新增 tutor schema、service 和 router 测试。
2. 复用 `AgenticRAGService` 实现课程级证据构建。
3. 增加多智能体闭环响应结构和 Mock LLM 降级。
4. 前端新增全局悬浮辅导组件和 API client。
5. 在 `AppLayout` 挂载并完成课程上下文绑定。
6. 增加样式和响应式处理。
7. 浏览器验证 `/courses`、知识图谱、学习路径、学习页、学习评估页。
