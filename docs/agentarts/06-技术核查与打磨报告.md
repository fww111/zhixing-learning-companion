## 三、AgentArts MCP 部署硬约束（这是本轮最关键的发现）

| 约束 | 官方原文要点 | 出处 |
| --- | --- | --- |
| 无状态 | `stateless_http=True`，以兼容平台会话管理与负载均衡 | 10_069 |
| 会话头 | 平台自动注入 `Mcp-Session-Id`，**服务端必须接受、不得拒绝** | 10_069 |
| 单端点 | `POST /mcp`，JSON-RPC 2.0；响应可为 `application/json` 或 `text/event-stream` | 10_069 / 10_126 |
| 健康检查 | `GET /ping`（官方示例用 `@mcp.custom_route("/ping", methods=["GET"])`）；网关默认按运行时配置端口探活 | 10_080 |
| Accept 头 | 客户端 `Accept` **必须同时含** `application/json` 和 `text/event-stream`，否则 **406** | 10_067 |
| Host / Origin | 网关转发的 Host 是运行时域名；官方示例禁用 DNS rebinding 保护并 patch `_validate_host`，否则 SDK 默认只允许 localhost | 10_080 |
| 鉴权 | 运行时调用带 `Authorization: Bearer {apikey}`（平台签发）与 `X-Hw-Agentarts-Session-Id`；自定义接入则支持「无需鉴权 / API Key / OAuth2.0」在平台侧配置 | 10_080 / 05_0136 |
| 端口 | 《MCP》写默认 **8000**，《制作镜像》示例用 **8080**，《MCP Server 部署》表格"默认 8000"。**以控制台运行时实际配置为准，用 `PORT` 环境变量对齐** | 10_069 / 10_080 / 10_126 |
| 容器 | `Host=0.0.0.0`、**ARM64 容器**（官方推荐 Ubuntu 22.04 ARM64 构建），镜像推到与 AgentArts **同区域的 SWR**（cn-southwest-2） | 10_069 / 10_080 |
| 公网 | 「自定义接入 MCP」要求服务**可通过公网地址访问**，平台无法访问内网/本地服务 | 05_0136 |
| 运行时 | 部署时"入栈协议"选 **MCP**（Agent 部署才是 HTTP / `/invocations`） | 10_080 / 10_126 |

### 关于"没服务器就没法验证 MCP"——这个前提可以拆掉

官方给了两条路径，**都不需要自己买 ECS**：

1. **运行时托管（推荐）**：把镜像推到 SWR → 在 AgentArts「智能体运行时」以入栈协议 MCP 部署 → 平台给出公网访问域名。平台负责服务器、探活、鉴权、负载均衡。
2. **低代码自定义接入**：填 MCP 服务的公网 URL。这个 URL 可以直接用第 1 步运行时给出的访问域名，**不必另起服务器**。

也就是说，只要开通 AgentArts → 构建并推送 ARM64 镜像 → 部署运行时，就能完成真正的云端 MCP 验证。当前真正的阻塞项不是"没有服务器"，而是**公测开通 / SWR 组织 / 区域选择 / 镜像构建**这几步准备工作。

> ⚠️ 另外，AgentArts 目前处于**公测阶段，需先申请公测**才能开通，且仅体验版可开通。这一步应尽早启动，避免卡住后续全部流程。

## 四、原有实现与官方契约的差距（已修）

| 差距 | 影响 | 处置 |
| --- | --- | --- |
| `Dockerfile` 一个镜像起 3 个进程、暴露 8100/8101/8102 | 运行时一个容器只探一个端口、只转发一个端口 → **后两个 Server 永远不可达** | ✅ 改为统一单端口入口 |
| 没有 `/ping` | 网关探活失败，实例被判不健康 | ✅ 新增 |
| 未禁用 DNS rebinding / patch Host 校验 | 云端请求 Host 非 localhost → 被 SDK 拒绝（必现） | ✅ 新增 |
| `MCP_ACCESS_TOKEN` guard 默认按本地 token 校验 | 平台带的是自己的 apikey → 全部 401；`/ping` 也被拦 | ✅ 改为 `MCP_AUTH_MODE=platform` 默认交给网关；`local` 模式才校验且放行 `/ping` |
| 三个 FastMCP 实例分散注册，无法合并 | 无法单端点交付 | ✅ 抽出 `TOOL_IMPLS` 注册表 + 统一 `server.py` |
| 端口写死 8100/8101/8102 | 无法与运行时控制台端口对齐 | ✅ `PORT` / `MCP_PORT` 覆盖，默认 8080 |
| `.env.example` 无 MCP 配置 | 部署时漏配 | ✅ 补齐 7 个变量 |

## 七、仍待处理的技术债（按优先级）

1. **身份可信映射（安全，最高优先级）**：MCP 工具的 `user_id` 仍是调用方自报的裸参数，仅靠 `ensure_course` 校验课程归属；平台工作流只要传别的 `user_id` 就能读写他人数据。本地冒烟测试的 "cross-user isolation" 只验证了「A 用户读不到 B 用户的课程」，**没有验证「调用方不能伪造 user_id」**。建议由 FastAPI 签发短期签名 token，MCP 侧校验后再取 `user_id`；或让 AgentArts 全局变量只传签名值。
2. **依赖与配置漂移**：`apps/mcp` 通过 `_bootstrap.py` 把 `apps/api` 塞进 `sys.path` 复用全量后端模块，但两套 `uv.lock` 都不含 `langgraph / pymilvus / torch`，任何触及向量检索的工具会 `ImportError` 或静默降级。根治方案是拆出独立 `domain` 包。另有 `.env` / `.env.example` / `config.py` 三套数据库口令不一致，`config.py` 还硬编码了明文口令。
3. **长任务不能进同步 MCP 工具**：`generate_package` / `TutorService.chat` / `answer_interview` 含 LangGraph、多次 LLM、`asyncio.run`、进程内 `ThreadPoolExecutor`，应改造成 `submit → job_id → poll` 双工具或留在 FastAPI。
4. **第三方知识库接入（建议新增创新点）**：按《第三方通用知识库接入规范》把自建「图谱约束 + MySQL 原文回表」链路做成正式第三方知识库，与平台知识库做 A/B 命中测试，直接对应赛题"知识接入"与创新性评分。
5. **评估闭环落地**：用官方推荐的 RAG 场景评估器组合（知识问答-真实准确、引用相关性、幻觉现象、工具选择质量）跑两版提示词对比，截图进 PPT。

## 八、下一步最小可行动作（不需要买服务器）

1. 申请 AgentArts 公测 → 开通体验版（**仅西南-贵阳一**），确认代金券/免费额度。
2. `docker build --platform linux/arm64 -f apps/mcp/Dockerfile -t zhixing-mcp:latest .`，本地先 `docker run -p 8080:8080` 跑一次 `protocol_smoke.py`（把 BASE 换成容器地址）确认镜像无误。
3. 创建 SWR 组织（同区域），打 tag 并 push。
4. 控制台「智能体运行时」→ 部署，入栈协议选 **MCP**，端口填 **8080**，健康检查 `/ping`。
5. 用官方 curl（`tools/list` / `tools/call`，带 `Authorization: Bearer {apikey}`）验证云端连通，把返回截图留作答辩证据。
6. 「我的资产 > MCP > 自定义接入」→ Streamable HTTP → 填运行时访问域名 → 调试 → 挂到工作流 MCP 节点（注意配异常分支）。
7. 资产广场确认实际模型 ID，完成 MaaS 鉴权配置，再发布应用 API 供 Demo 前端调用。
