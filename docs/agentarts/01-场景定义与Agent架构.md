# 01 场景定义与 Agent 架构

> 华为 ICT 大赛赛题二：基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用
> 本文档对应提交材料中的"Agent 设计方案：场景定义、编排思路、工作流架构、模型与资产选择"。

## 1. 场景识别

### 1.1 场景名称

**「知行学习伙伴」——面向高等教育的个性化学习多智能体系统**

领域归属：行业赋能型（教育）+ 生活服务型（学习辅助），应用形态为 Web 可视化 Demo。

### 1.2 真实痛点

1. **资源错配**：学生面对海量课程资料无法筛选出匹配自身基础和进度的内容，"看不懂的太深、看懂的太浅"。
2. **集体讲授难以因材施教**：课堂节奏统一，学生在知识掌握和能力提升上差距持续拉大。
3. **生成式 AI 直接学习存在幻觉风险**：通用大模型问答没有课程证据约束，讲解可能偏离教材，练习题可能超纲或答案错误。
4. **学习过程数据闲置**：测验、错题、耗时等行为数据没有被用于持续修正学习方案。

### 1.3 解决思路

以课程教材构建**平台知识库 + 课程知识图谱**双证据源，由多智能体协作完成
"画像访谈 → 证据约束的多模态资源生成 → 动态学习路径 → 学习评估 → 画像随学随新"
的学习闭环；所有面向学生的生成内容必须能回溯到课程原文 chunk 或知识图谱关系，从机制上压制幻觉。

### 1.4 目标用户与演示课程

- 目标用户：高校本科生（计算机类专业为演示对象）。
- 演示课程：`C++算法学习`（主，覆盖 8 章 33 个知识点的自建教材语料，见 `data/seed/cpp_algorithms/`）；`Python程序设计` 为辅助验证课程（验证多课程数据隔离）。
- 《C++算法学习》语料已按"章→节"结构编写（每节含概念讲解、可编译 C++ 示例、易错点），可直接上传平台知识库；知识图谱种子（节点/前置关系）见 `data/seed/cpp_algorithms/cpp_algorithms.json`，可用 `apps/mcp/scripts/seed_cpp_course.py` 写入本地 MySQL + Neo4j。

## 2. Agent 架构设计

### 2.1 总体架构

采用 **AgentArts 多智能体应用（多 Agent 控制器）+ 4 个子应用 + 3 个自定义 MCP Server** 的分层架构：

```text
学生（React 可视化 Demo 页面 / AgentArts 网页发布）
        │ SSE 流式
        ▼
┌─────────────────────────────────────────────────────────┐
│ AgentArts 多智能体应用（多 Agent 控制器）                    │
│ 意图识别路由：                                            │
│   ① 画像访谈意图 → 画像访谈工作流                           │
│   ② 资源学习意图 → 个性化资源生成工作流（核心）              │
│   ③ 疑难求助意图 → 智能辅导子智能体                          │
│   ④ 路径与评估意图 → 学习路径与评估工作流                    │
└─────────────────────────────────────────────────────────┘
   │                │                │              │
 平台知识库      MCP: graph-server  MCP: profile-server  MCP: assessment-server
 （课程语料      （知识图谱约束/     （画像持久化/         （评估/掌握度/
 语义检索）       原文证据回表）      画像随学随新）        学习路径规划）
        │
   插件/HTTP：OpenMAIC 标准课堂生成（3D 可视化/仿真/游戏化课堂）
```

### 2.2 多 Agent 分工

| Agent/子应用 | 类型 | 职责 | 依赖的工具与知识 |
| --- | --- | --- | --- |
| 多 Agent 控制器 | 多智能体应用 | 意图识别与分发，全局上下文 | — |
| 画像访谈 Agent | 对话型工作流 | 首问固定 → 动态追问 → 画像抽取 → 确认持久化 | 大模型节点、提问器节点、MCP: profile-server |
| 资源生成 Agent（组） | 任务型工作流 | 分析规划 → 检索 → 并行生成 6 类资源 → 事实校验 → 教学适配 → 辩论 → 决策 | 平台知识库、MCP: graph-server、并行聚合 + 反思精炼范式 |
| 智能辅导 Agent | 单智能体 | 课程证据约束下的多模态答疑 | 平台知识库、MCP: graph-server、视觉模型 |
| 路径与评估 Agent | 任务型工作流 | 学习路径规划/重规划、评估提交与解读 | MCP: assessment-server |

### 2.3 资源生成闭环（核心工作流）的编排范式映射

本项目最重要的创新是把"防幻觉多智能体评审"映射到 AgentArts 原生工作流范式：

| 项目闭环阶段 | AgentArts 范式/节点 |
| --- | --- |
| 分析规划（读画像 + 图谱约束） | 大模型节点 + MCP 工具节点 |
| 多路检索 | 知识检索节点（平台知识库）+ MCP 节点（图谱扩展查询 + MySQL 原文回表） |
| 6 类资源并行生成 | **并行聚合**范式：文档 / 思维导图 / 视频脚本 / 代码实操 / 练习题 / 拓展阅读 6 分支 |
| 事实校验 → 教学适配 → 辩论 → 决策 | **反思精炼循环**：校验分支不通过则回到检索/生成，最多 2 轮 |
| 双模型辩论 | 大模型节点 A（DeepSeek-V4）与大模型节点 B（GLM-5）交叉评审 |

### 2.4 六类个性化资源（满足赛题 ≥5 类要求）

1. 专业课程讲解文档（Markdown）
2. 知识点思维导图（树状结构 JSON → 前端渲染）
3. 不同类型练习题目（选择/填空/编程，含 `correct_answer_index`）
4. 拓展阅读材料
5. 多模态教学视频/动画（视频脚本 + 分镜 → OpenMAIC 标准课堂 + 课堂语音 TTS）
6. 代码类实操案例（浏览器可运行代码实验）

### 2.5 学生画像（满足 ≥6 维度、随学随新）

画像维度：专业、年级、学习目标、知识基础、薄弱点、学习风格、认知风格、资源偏好、时间约束、评估偏好、动机、知识图谱关注点、置信度、完成度（14 维）。

"随学随新"机制：AgentArts 侧只负责对话抽取与确认；持久化与增量更新由 MCP: profile-server 完成——每次评估/练习/课堂完成事件都会触发画像维度更新（`record_profile_event`），并返回"是否需要重规划路径"信号给工作流。

## 3. 模型与资产选择

| 资产 | 选择 | 理由 |
| --- | --- | --- |
| 主推理模型 | 华为云 MaaS `DeepSeek-V4-Pro` | 长文本生成与结构化抽取能力强；OpenAI 协议，与原系统提示词资产兼容 |
| 辩论/校验模型 | MaaS `GLM-5` | 与主模型异源，交叉验证更能暴露幻觉；体现模型路由策略 |
| Embedding/检索 | AgentArts 平台知识库语义检索（含精排） | 平台托管、带命中测试；免自建 Milvus 运维 |
| 视觉理解 | MaaS 多模态模型（GLM-4.5V / Qwen-VL 系） | 辅导场景图片题目理解 |
| 自定义 MCP | graph-server / profile-server / assessment-server（Python SDK，streamableHttp） | 承载平台不具备的业务深度：知识图谱约束、原文证据回表、掌握度与路径规划 |
| 插件 | OpenMAIC 课堂生成插件（HTTP） | 生成 3D 可视化/仿真/游戏化多智能体课堂 |
| 评测资产 | AgentArts 评测集 + 评估器（正确性、幻觉、任务完成度） | 对资源生成质量做离线评估，形成"评估→优化"闭环证据 |

## 4. 与平台既有方案的差异化（创新点）

1. **知识图谱约束的 Agentic RAG**：平台知识库是平面向量检索；本系统用 MCP graph-server 注入前置/后继/章节约束，并把最终证据回表到 MySQL 原文 chunk，保证"每个知识点讲什么、讲多深、先讲什么"都由图谱决定。
2. **双模型辩论交叉验证**：同一资源由两个异源大模型分别做事实校验与教学适配评审，冲突进入辩论节点，决策节点给出 accepted / retrieve_more / revise 三态路由（工作流判断节点）。
3. **掌握度驱动的动态路径重规划**：评估未达标自动插入"薄弱点专项任务"（1.1.1 → 1.1.1 薄弱点专项 → 1.1.2），画像随学随新，路径自动重排。
4. **多智能体标准课堂**：通过插件接入 OpenMAIC，把生成大纲变成 3D 可视化/仿真/游戏化的多智能体课堂，而非纯文本聊天。
5. **课程级数据隔离**：画像、证据、图谱、掌握度、路径全部按 `user_id + course_id` 隔离，支持多课程、多学生真实使用。
