## 1. 已移植

### 1.1 知识库分块预设体系（对应评分项：知识库构建方法）

**来源**：`AI-Interview/src/knowledge/chunking/ragflow_like/`（RAGFlow-like 四预设：general/qa/book/laws + 三层参数合并 + 引擎版本快照）。

**本项目实现**：`apps/api/app/services/chunking_service.py`（重写）

| 预设 | 说明 | 教育场景 |
| --- | --- | --- |
| `general` | 定长窗口 + **百分比重叠**（`overlap_percent`，窗口回退步进防重复尾巴） | 讲义、普通正文 |
| `qa` | 抽取"问题：/答案："前缀对与疑问句标题对，统一为 `问题：…\n回答：…` 格式；**抽不到任何 QA 对时整体降级 general** | 题库、FAQ、复习问答；下游可反向解析实现"随机抽题"工具（伯乐 `pick_random_technical_question` 的前置） |
| `book` | 按页标题分节 → 节内层级合并 → 超长节**三级保护**（句子级切分 → 字符级硬切，防 embedding 超长） | 教材、章节化讲义 |

关键工程机制（直接照搬伯乐设计）：

- **三层参数合并** `resolve_chunk_params(kb_default, file_override, request_override)`：优先级 request > file > KB 默认，QA/book 强制无重叠，参数夹紧防呆。
- **分块引擎版本快照** `CHUNK_ENGINE_VERSION = "v2-presets"`：每个材料的分块参数随快照落库，日后换分块算法可按版本重索引。
- `chunk_pages`（旧版行为）保持不变，既有管线与测试零破坏；新管线走 `chunk_pages_with_preset`。
- 上传接口 `POST /api/courses/{course_id}/materials` 新增 `chunk_preset` 表单参数，经 `MaterialTaskQueue.enqueue(chunk_params=…)` 透传到解析任务。

### 1.2 知识库检索能力自动评估（对应评分项：知识库构建方法 + 效果评估）

**来源**：`AI-Interview/src/services/evaluation_service.py`（anchor+邻居干扰自动构造 benchmark → recall/f1@k → error_only 坏例分析）+ `src/utils/evaluation_metrics.py`。

**本项目实现**（新增，2026-11）：

- 模型：`apps/api/app/models/kb_evaluation.py`（`kb_benchmark_items` / `kb_evaluation_runs` / `kb_evaluation_details` 三表）
- 服务：`apps/api/app/services/kb_evaluation_service.py`
  - `generate_benchmark`：从课程 chunk 随机选 anchor + 3 个干扰段落，LLM 生成 `{query, gold_answer}`（gold_chunk_ids 固定校验为 anchor；LLM 不可用时退化为"标题讲解式"查询，来源标记 `fallback`）
  - `create_run / run_evaluation`：逐题调用检索器（`semantic` 走 Milvus 语义检索，`mysql_like` 走关键词评分兜底），计算 **recall@1/3/5/10 与 f1@k**，逐题明细落库
  - **坏例分析**：`recall@5 < 0.5` 的条目标记 error，`GET runs/{id}?error_only=true` 直接筛出——指导分段策略与检索调优
- 路由：`POST/GET /api/courses/{course_id}/kb-evaluation/benchmark`、`POST/GET /api/courses/{course_id}/kb-evaluation/runs`
- 设计约束：LLM JSON 解析失败自动降级 fallback（评估集永远可生成）；评估任务同步小任务化（演示/答辩场景），未引入队列依赖

**参赛价值**：这是"回答'课程知识库检索好不好用'的唯一客观手段"——答辩时可用同一课程库在不同分段策略/检索器下跑两次评估，对比报告直接进 PPT；坏例清单则演示"数据驱动的知识库调优"闭环。

### 1.3 其他已采纳的伯乐实践

- **LLM JSON 容错**：本项目 `LLMClient.complete_json` 原有 json_repair 式兜底，与伯乐 `json_repair` 全局容错思路一致，评估服务直接复用。
- **Mock LLM 分层**：评估集生成遵循项目既有约定——`LLMClient` 内部处理 mock，服务层不再重复判断，保证"无外部 API 也能跑通全流程"。

## 3. 测试与验证

- `apps/api/tests/test_chunking_presets.py`（10 用例）：三层合并优先级、通用重叠与尾部去重、QA 前缀对/疑问句标题对/去重/降级、教材分节合并与三级保护、前端选项
- `apps/api/tests/test_kb_evaluation.py`（7 用例）：fallback 与 LLM 双路 benchmark 构造、chunk 不足拒绝、语义/关键词两路检索评估指标、坏例标记与 error_only 筛选、检索器失败落库 failed
- 全量回归：`test_courses_api` 70/70 通过；剩余失败仅为本机缺 `D:\softbei\a3` 路径的 5 个 vector_service 环境用例（原机器通过）

## 4. AgentArts 侧映射

- 平台知识库分段配置对齐本项目预设结论：教材类用"按标题分层"（=book 预设思想）、题库类用 QA 分段（=qa 预设思想）
- 评估闭环对应《02-AgentArts工作流搭建蓝图》§8 的评测集构建：本地评估报告（recall/f1@k + 坏例清单）与平台评估器（正确性/幻觉）互补，构成"检索质量 + 生成质量"双层证据
